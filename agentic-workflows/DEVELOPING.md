# Developing Agentic Workflows

## Architecture

```text
.github/workflows/
├── gh-aw-fragments/                    # Shared prompt fragments
│   ├── formatting.md
│   ├── rigor.md
│   ├── mcp-pagination.md
│   ├── messages-footer.md
│   └── safe-output-add-comment.md
├── gh-aw-docs-check.md                # Workflow source
├── gh-aw-docs-check.lock.yml          # Compiled output
├── gh-aw-issue-triage.md              # Workflow source
├── gh-aw-issue-triage.lock.yml        # Compiled output
├── compile-check.yml                   # PR validation
├── check-aw-updates.yml               # Weekly recompilation
└── ... (other CI workflows)

agentic-workflows/
├── docs-check/
│   ├── example.yml                     # Trigger template for callers
│   └── README.md                       # Usage docs
├── issue-triage/
│   ├── example.yml
│   └── README.md
├── README.md                           # Workflow index
└── DEVELOPING.md                       # This file
```

**Workflow sources** (`.github/workflows/gh-aw-*.md`) are agent definitions that import shared fragments. Each file contains the engine config, `workflow_call` trigger, permissions, tools, MCP servers, safe-outputs, and the full agent prompt.

**Shared fragments** (`.github/workflows/gh-aw-fragments/`) provide reusable prompt sections and configuration. Workflows import them via `imports:` in the frontmatter.

**Compiled lock files** (`.github/workflows/gh-aw-*.lock.yml`) are generated by `gh aw compile`. These are what consumer repos execute via `uses:`.

**Trigger templates** (`agentic-workflows/<name>/example.yml`) are plain YAML files that consumer repos copy into their `.github/workflows/`. They define event triggers and call the compiled `.lock.yml` via `uses:`.

## Cross-repo `workflow_call` and `inlined-imports`

Our workflows are called cross-repo via `workflow_call`. By default, the gh-aw compiler emits `runtime-import` directives that resolve from the caller's filesystem — which fails cross-repo because the caller doesn't have our fragments or `.md` sources.

The fix: every workflow `.md` must include `inlined-imports: true` in the frontmatter. This embeds all imported content directly into the lock file at compile time, making it fully self-contained.

```yaml
---
inlined-imports: true
imports:
  - gh-aw-fragments/formatting.md
  - gh-aw-fragments/rigor.md
  ...
```

**Trade-off**: the lock file is larger, and you must recompile after any fragment change. But cross-repo invocation works.

## Local Development

### Prerequisites

- [GitHub CLI](https://cli.github.com/) (`gh`)

### Setup

```bash
make setup    # installs gh-aw extension
```

### Editing workflows

1. Edit `.md` files in `.github/workflows/gh-aw-*.md` or fragments in `.github/workflows/gh-aw-fragments/`
2. Run `make compile`
3. Verify 0 errors, 0 warnings
4. Commit both the source `.md` and the generated `.lock.yml`

### Adding a new workflow

1. Create `.github/workflows/gh-aw-<name>.md` with `inlined-imports: true`, imports, tools, network, safe-outputs, and prompt
2. Create `agentic-workflows/<name>/example.yml` with event triggers and:
   ```yaml
   uses: elastic/docs-actions/.github/workflows/gh-aw-<name>.lock.yml@v1
   ```
3. Create `agentic-workflows/<name>/README.md` with trigger details, inputs, and safe outputs
4. Run `make compile`
5. Commit source files + generated `.lock.yml`

### workflow_call Convention

All workflows include a `workflow_call` trigger with standard inputs:

```yaml
on:
  workflow_call:
    inputs:
      additional-instructions:
        description: "Repo-specific instructions appended to the agent prompt"
        type: string
        required: false
        default: ""
      setup-commands:
        description: "Shell commands to run before the agent starts"
        type: string
        required: false
        default: ""
      messages-footer:
        description: "Footer appended to all agent comments and reviews"
        type: string
        required: false
        default: ""
    secrets:
      COPILOT_GITHUB_TOKEN:
        required: true
```

### Shared fragments

| Fragment | Purpose |
| --- | --- |
| `gh-aw-fragments/formatting.md` | Response formatting rules |
| `gh-aw-fragments/rigor.md` | Accuracy & evidence standards |
| `gh-aw-fragments/mcp-pagination.md` | MCP token limit guidance and pagination patterns |
| `gh-aw-fragments/messages-footer.md` | Wires the `messages-footer` input to `safe-outputs.messages.footer` |
| `gh-aw-fragments/safe-output-add-comment.md` | Limitations for `add-comment` |

### CI

- **`compile-check.yml`** — runs on PRs that touch `.github/workflows/gh-aw-*`. Compiles and fails if the committed `.lock.yml` is out of date.
- **`check-aw-updates.yml`** — runs weekly. Recompiles all lock files and opens a PR if the gh-aw compiler produces different output.
