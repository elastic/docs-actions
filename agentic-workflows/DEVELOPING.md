# Developing Agentic Workflows

## Architecture

```text
.github/workflows/
├── gh-aw-docs-check.md                # Workflow source (self-contained)
├── gh-aw-docs-check.lock.yml          # Compiled output
├── gh-aw-issue-triage.md              # Workflow source (self-contained)
├── gh-aw-issue-triage.lock.yml        # Compiled output
├── compile-check.yml                   # PR validation
├── check-aw-updates.yml               # Weekly recompilation
└── ... (other CI workflows)

agentic-workflows/
├── docs-check/
│   ├── example.yml                     # Trigger template for callers
│   └── README.md                       # Usage docs
├── issue-triage/
│   ├── example.yml
│   └── README.md
├── README.md                           # Workflow index
└── DEVELOPING.md                       # This file
```

**Workflow sources** (`.github/workflows/gh-aw-*.md`) are self-contained agent definitions. Each file contains the engine config, `workflow_call` trigger, permissions, tools, MCP servers, safe-outputs, and the full agent prompt. All content is inlined — no fragment imports.

**Compiled lock files** (`.github/workflows/gh-aw-*.lock.yml`) are generated by `gh aw compile`. These are what consumer repos execute via `uses:`.

**Trigger templates** (`agentic-workflows/<name>/example.yml`) are plain YAML files that consumer repos copy into their `.github/workflows/`. They define event triggers and call the compiled `.lock.yml` via `uses:`.

## Why no imports/fragments

The gh-aw compiler's `imports:` directive creates `runtime-import` references in the lock file. At runtime, these are resolved from the **caller's** repository filesystem — not the host repo where the lock file lives. Since our workflows are called cross-repo via `workflow_call`, the caller doesn't have the imported files, and the runtime fails.

To avoid this, all prompt content is inlined directly in each `.md` source. If you need to share text across workflows, copy-paste it. This is a known limitation of cross-repo `workflow_call` with gh-aw runtime imports.

## Local Development

### Prerequisites

- [GitHub CLI](https://cli.github.com/) (`gh`)

### Setup

```bash
make setup    # installs gh-aw extension
```

### Editing workflows

1. Edit `.md` files in `.github/workflows/gh-aw-*.md`
2. Run `make compile`
3. Verify 0 errors, 0 warnings
4. Commit both the source `.md` and the generated `.lock.yml`

### Adding a new workflow

1. Create `.github/workflows/gh-aw-<name>.md` with all content inlined (no `imports:`)
2. Create `agentic-workflows/<name>/example.yml` with event triggers and:
   ```yaml
   uses: elastic/docs-actions/.github/workflows/gh-aw-<name>.lock.yml@v1
   ```
3. Create `agentic-workflows/<name>/README.md` with trigger details, inputs, and safe outputs
4. Run `make compile`
5. Commit source files + generated `.lock.yml`

### workflow_call Convention

All workflows include a `workflow_call` trigger with standard inputs:

```yaml
on:
  workflow_call:
    inputs:
      additional-instructions:
        description: "Repo-specific instructions appended to the agent prompt"
        type: string
        required: false
        default: ""
      setup-commands:
        description: "Shell commands to run before the agent starts"
        type: string
        required: false
        default: ""
      messages-footer:
        description: "Footer appended to all agent comments and reviews"
        type: string
        required: false
        default: ""
    secrets:
      COPILOT_GITHUB_TOKEN:
        required: true
```

### Common frontmatter sections

Since we don't use imports, here are the standard sections to include in every workflow `.md`:

**Messages footer** (in `safe-outputs:`):
```yaml
safe-outputs:
  messages:
    footer: "${{ inputs.messages-footer || '---\n[Docs automation](https://github.com/elastic/docs-actions) | [From workflow: {workflow_name}]({run_url})\n\nReact with 👍 if helpful, 👎 if not.' }}"
```

**Elastic Docs MCP server** (if the workflow searches docs):
```yaml
mcp-servers:
  elastic-docs:
    url: "https://www.elastic.co/docs/_mcp/"
    allowed:
      - "SemanticSearch"
      - "GetDocumentByUrl"
      - "FindRelatedDocs"
      - "FindInconsistencies"
```

### CI

- **`compile-check.yml`** — runs on PRs that touch `.github/workflows/gh-aw-*`. Compiles and fails if the committed `.lock.yml` is out of date.
- **`check-aw-updates.yml`** — runs weekly. Recompiles all lock files and opens a PR if the gh-aw compiler produces different output.
