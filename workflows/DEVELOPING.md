# Developing Agentic Workflows

## Architecture

```text
workflows/                              # Library of agentic workflow sources
├── fragments/                          # Shared prompt fragments
│   ├── docs-tools.md                   # Elastic Docs MCP server config
│   ├── formatting.md                   # Response formatting rules
│   ├── rigor.md                        # Accuracy & evidence standards
│   ├── mcp-pagination.md               # MCP token limit guidance
│   ├── messages-footer.md              # Message footer wiring
│   ├── runtime-setup.md                # Language runtime detection
│   ├── scheduled-report.md             # Base audit framework
│   └── safe-output-*.md                # Safe output constraints
├── docs-check/
│   ├── gh-aw-docs-check.md             # Workflow source
│   ├── example.yml                     # Trigger template for callers
│   └── README.md                       # Usage docs
├── README.md                           # Workflow index
└── DEVELOPING.md                       # This file

.github/workflows/                      # Compiled outputs + CI
├── gh-aw-docs-check.lock.yml           # Generated by compile
├── compile-check.yml                   # PR validation
├── check-aw-updates.yml                # Weekly recompilation
└── ... (other CI workflows)
```

**Workflow sources** (`workflows/<name>/gh-aw-<name>.md`) are self-contained agent definitions. Each file contains the engine config, `workflow_call` trigger, permissions, tools, MCP servers, safe-outputs, and the full agent prompt. They import shared fragments using `gh-aw-fragments/` paths.

**Trigger templates** (`workflows/<name>/example.yml`) are plain YAML files that consumer repos copy into their `.github/workflows/`. They define event triggers and call the compiled `.lock.yml` via `uses:`.

**Shared fragments** (`workflows/fragments/`) provide cross-workflow configuration. During compilation, they're copied to `.github/workflows/gh-aw-fragments/` where the compiler expects them.

**Compiled lock files** (`.github/workflows/gh-aw-*.lock.yml`) are the output of `scripts/compile.sh`. These are what consumer repos actually execute via `uses:`.

## How Compilation Works

The `gh-aw` compiler expects source files in `.github/workflows/`. Since our sources live in `workflows/`, the compile script bridges the gap:

1. Copies `workflows/fragments/` → `.github/workflows/gh-aw-fragments/`
2. Copies `workflows/*/gh-aw-*.md` → `.github/workflows/`
3. Runs `gh-aw compile`
4. Removes the copies (lock files remain)

The `.md` copies and `gh-aw-fragments/` directory in `.github/workflows/` are gitignored — only the `.lock.yml` outputs are committed there.

## Local Development

### Prerequisites

- [Go](https://go.dev/dl/) (for the gh-aw compiler)

### Setup

```bash
make setup    # installs gh-aw compiler + actionlint to bin/
```

### Editing workflows

1. Edit workflow `.md` files in `workflows/<name>/`, fragments in `workflows/fragments/`, or triggers in `workflows/<name>/example.yml`
2. Run `make compile`
3. Verify 0 errors, 0 warnings
4. Commit both the source files and the generated `.lock.yml`

### Adding a new workflow

1. Create `workflows/<name>/gh-aw-<name>.md` with imports, tools, network, safe-outputs, and prompt
2. Create `workflows/<name>/example.yml` with event triggers and:
   ```yaml
   uses: elastic/docs-actions/.github/workflows/gh-aw-<name>.lock.yml@v1
   ```
3. Create `workflows/<name>/README.md` with trigger details, inputs, and safe outputs
4. Run `make compile`
5. Commit source files + generated `.lock.yml`

### workflow_call Convention

All workflows include a `workflow_call` trigger with standard inputs:

```yaml
on:
  workflow_call:
    inputs:
      additional-instructions:
        description: "Repo-specific instructions appended to the agent prompt"
        type: string
        required: false
        default: ""
      setup-commands:
        description: "Shell commands to run before the agent starts"
        type: string
        required: false
        default: ""
      messages-footer:
        description: "Footer appended to all agent comments and reviews"
        type: string
        required: false
        default: ""
    secrets:
      COPILOT_GITHUB_TOKEN:
        required: true
```

### Import rules

- The compiler supports **2-level** import paths (`gh-aw-fragments/file.md`). Paths with 3+ segments are interpreted as remote GitHub references.
- `engine:`, `on:`, `concurrency:`, `timeout-minutes:`, `strict:`, `roles:` are **not importable** — they must be in the workflow `.md`.
- `safe-outputs:` in the main workflow override imported defaults. `tools:` merge additively.

### CI

- **`compile-check.yml`** — runs on PRs that touch `workflows/**/*.md`. Compiles and fails if the committed `.lock.yml` is out of date.
- **`check-aw-updates.yml`** — runs weekly. Recompiles all lock files and opens a PR if the gh-aw compiler produces different output.
